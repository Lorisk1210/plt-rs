# `<name regex> | <message regex> | why`. `cargo xtask diff --types`

# Instance attributes built lazily. The class holds a non-data descriptor
# (`_transform_trees.TreeAttribute`) that builds the figure's or the Axes'

# the instance's `__dict__`, as matplotlib's does, and is read and assigned
# there. Only a read off the class itself shows the descriptor.

# A renderer's converter of texts to paths, which matplotlib's constructor

# matplotlib binds these by importing them from its private modules (`_cm`,
# `_cm_listed`, `_cm_multivar`, `_cm_bivar`), which stubtest passes over;
# pltrs computes them in `cm` from pltrs (Rust)'s definitions. The names and
# values are the same (`cargo xtask diff --docs` compares module values).
^matplotlib\.cm\.(datad|cmaps_listed|multivar_cmaps|bivar_cmaps)$ | ^is not present in stub$ | matplotlib imports these tables from private modules; pltrs builds the same tables in cm itself

# matplotlib's FT2Font and FT2Image are C++ (pybind11): stubtest cannot read
# their signatures, so where matplotlib's stub differs from its own run time
# it passes unseen. pltrs has the run time's signatures: those of the
# signature lines pybind11 writes (`load_glyph(self, glyph_index, flags=...)`,
# `__init__(self, filename, hinting_factor=None, *, ...)`, which `cargo xtask
# diff --docs` compares) and of the bindings in `src/ft2font_wrapper.cpp`
# (`draw_glyph_to_bitmap`'s and `draw_glyphs_to_bitmap`'s `antialiased`
# after `py::kw_only()`, `_layout`'s `string` with `features` and
# `language` after it); and the buffer protocol both classes have
# (`__release_buffer__`, a C slot in matplotlib).
^matplotlib\.ft2font\.FT2Font\.(__init__|load_glyph|draw_glyphs?_to_bitmap|_layout)$ | ^is inconsistent, stub (does not have parameter "hinting_factor"|parameter "antialiased" is not keyword-only|parameter "glyphindex" differs from runtime parameter "glyph_index"|parameter "text" differs from runtime parameter "string"|parameter "(features|language)" is not keyword-only)$ | matplotlib's C++ run time has this signature, which its stub misdescribes and stubtest cannot read there
^matplotlib\.ft2font\.(FT2Font|FT2Image)\.__release_buffer__$ | ^is not present in stub$ | matplotlib's classes have it too, as a C slot stubtest passes over

# A spine binds its native spine in `__new__`, before the constructor of a
# program's subclass reads it (cartopy's `GeoSpine`). Constructing,
# subclassing and pickling a spine behave as matplotlib's, whose `__new__` is
# object's.
^matplotlib\.spines\.Spine\.__new__$ | ^is inconsistent, (stub does not have parameter "(axes|spine_type|path)"|stub parameter "cls" differs from runtime parameter "self")$ | binds the native spine before a program's subclass constructor reads it; construction behaves as matplotlib's
